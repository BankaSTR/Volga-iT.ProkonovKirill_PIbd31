# Volga IT. Автоматизация тестирования (Python)

Проект полуфинала по заданию SimbirSoft. Python 3.12+, Selenium 4, Pytest,
Page Object Model, Allure. Автор: Проконов Кирилл, ПИбд-31.

Тестируется настоящий сайт [Practice Automation](https://practice-automation.com/):
[Calendars](https://practice-automation.com/calendars/),
[Modals](https://practice-automation.com/modals/),
[Ads](https://practice-automation.com/ads/).
Дополнительно [Form Fields](https://practice-automation.com/form-fields/) закрывает
отдельное требование задания Automation Tools → Message.

## Быстрый запуск

Нужны Python **3.12 или новее**, установленный Chrome или Firefox и доступ в Интернет.
Драйвер подходящей версии автоматически получает Selenium Manager. Расширения и
блокировщики рекламы в чистый профиль тестового браузера не устанавливаются.
Прямые зависимости закреплены в `requirements.txt`, транзитивные — в `constraints.txt`.

Windows PowerShell:

```powershell
git clone https://github.com/BankaSTR/Volga-iT.ProkonovKirill_PIbd31.git
cd Volga-iT.ProkonovKirill_PIbd31
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest
```

Linux / macOS:

```bash
git clone https://github.com/BankaSTR/Volga-iT.ProkonovKirill_PIbd31.git
cd Volga-iT.ProkonovKirill_PIbd31
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest
```

Активация окружения в Windows необязательна: команды ниже можно выполнять через
`.\.venv\Scripts\python.exe` и `.\.venv\Scripts\ruff.exe` соответственно.

```bash
python -m pytest --browser=firefox
python -m pytest --headed                   # видимое окно
python -m pytest -m smoke                   # основные пользовательские пути
python -m pytest -m negative                # только негативные проверки
python -m pytest tests/test_calendar.py
python -m pytest -n 2 --dist=loadfile        # два независимых браузера
python -m pytest --timeout=30 --page-load-timeout=90
ruff check .
ruff format --check .
```

`--base-url` (или `BASE_URL`) меняет адрес сервера. `--browser-binary` позволяет
указать путь к браузеру, `--driver-path` — путь к заранее скачанному совместимому
драйверу. Без этих аргументов используется Selenium Manager. Первый запуск требует
доступа к серверам загрузки драйверов. Кэш Selenium Manager находится вне репозитория.

## Allure

`pytest` автоматически сохраняет результаты в `allure-results/`. Каждый тест имеет
понятное русское название, страницу/feature, параметры и шаги. При ошибках теста
или подготовки страницы прикладываются **PNG-скриншот, HTML DOM, URL и capabilities**.
Если сам браузер не удалось запустить, в отчёте остаётся исходная ошибка запуска;
снимок несуществующего окна получить невозможно. Ошибка сбора диагностики не заменяет
исходную ошибку теста. Профиль браузера закрывается даже при падении теста.

Для HTML-отчёта нужны Java 8+ и Allure CLI 2 (Node.js нужен только для установки CLI):

```bash
npm install --global allure-commandline@2.34.1
allure generate allure-results --clean -o allure-report
allure open allure-report
```

Для независимого нового прогона можно использовать отдельную папку:

```bash
python -m pytest --alluredir=artifacts/run-01
allure serve artifacts/run-01
```

Не объединяйте результаты разных прогонов в одной папке: Allure покажет их вместе.
На CI рабочая папка каждого задания создаётся заново. GitHub Actions запускает
Chrome и Firefox на Python 3.12; даже при падении тестов сохраняются HTML Allure,
исходные результаты, скриншоты и JUnit XML в артефактах `reports-chrome` / `reports-firefox`.
Архив нужно распаковать и открыть командой `allure open <путь-к-allure-report>`.

## Архитектура и принципы

```text
pages/
  base.py          открытие страницы, явные ожидания, ввод
  calendar.py      дата, год/месяц/день, пагинация, отправка
  dialog.py        общий компонент Popup Maker
  modals.py        простое окно и контактная форма
  ads.py           отложенная реклама
  form_fields.py   чтение списка Selenium и заполнение Message
tests/
  conftest.py      CLI, браузер, фикстуры, диагностика Allure
  test_calendar.py
  test_modals.py
  test_ads.py
  test_form_fields.py
.github/workflows/ui-tests.yml
```

- Каждый тест получает **свой WebDriver и чистый профиль**. Порядок запуска и результат
  соседнего теста не влияют на состояние. Параллельный запуск не делит WebDriver.
- В Page Object находятся локаторы и действия; в тестах — ожидаемые результаты.
  Локаторы формы ограничены её окном: скрытые копии форм на сайте не перехватывают ввод.
- Используются явные ожидания состояний. Implicit wait равен нулю; `time.sleep`,
  принудительных JS-кликов и автоматических повторных прогонов тестов нет.
- JavaScript применяется для чтения готовности документа, часов/геометрии браузера,
  окончания штатной анимации и прокрутки элемента в центр экрана (сайт использует
  плавную прокрутку). Выбор дат, заполнение, закрытие и отправка выполняются
  пользовательскими действиями Selenium.
- Отрицательные проверки наблюдают окно в течение интервала, чтобы не пропустить
  отложенное закрытие/повторное появление. Это условные ожидания с ограниченным сроком.
- Адреса электронной почты используют зарезервированный домен `example.com`.
  Это UI-тесты публичного учебного сайта, а не нагрузочная проверка.

## Анализ функционала и границы ожиданий

На дату исследования календарь Jetpack — текстовое поле с форматом `YYYY-MM-DD` и
виджетом `.dp`. Можно выбрать год, месяц и день либо перелистывать месяцы. Дата не
является обязательным полем, однако целиком пустая форма не отправляется. Общая
ошибка в однополевой форме скрыта настройкой Jetpack; тест не требует её появления.
Проверяется
выбор високосного дня, начало/конец года, прошедшая и будущая даты. «Сегодня» берётся
из локального времени **браузера**, а не из даты машины, на которой запускается Pytest.

Простое окно и контактная форма используют Popup Maker. В форме обязателен только
Name; Email и Message необязательны. Escape разрешён для формы и запрещён для простого
окна. Закрытие окна без отправки сохраняет заполненные поля в рамках этой страницы.

Реклама появляется автоматически примерно через **4,5 секунды** после инициализации
страницы. Escape и нажатие на подложку отключены настройками упражнения. Крестик
закрывает окно; в той же загрузке страницы реклама больше не появляется. Новая
загрузка снова запускает таймер. Негативные тесты здесь проверяют запрет действий,
поскольку реклама не содержит полей для некорректного ввода.

Automation Tools находится именно на **Form Fields**, поэтому для пункта 5 задания
добавлен самостоятельный сквозной тест. Он находит `<li>` после подписи Automation
tools через Selenium, читает `.text`, сохраняет порядок, объединяет значения `", "`,
проверяет точное значение Message и подтверждение отправки в JavaScript alert.
Список названий в коде не зашит.

## Тестовые сценарии

В каждой строке указаны ID, действие и проверяемый результат. Для всех сценариев
предусловие: новый браузер без расширений, открыта указанная страница. Если указано
«окно», сначала выполняется его штатное открытие. Параметризованные строки являются
отдельными тестовыми случаями и имеют отдельные записи в Allure.
